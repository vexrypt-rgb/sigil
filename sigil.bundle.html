SIGIL

Sealed messages for open chats and Minecraft whispers. Everything stays in this browser.

Minecraft public chat and whispers cap a line at 256 characters. Long messages split into fragments. Paste each fragment as its own chat line. In plain circle mode the S2 sender name is sealed, but any circle member can claim any name. Signed circle (S2S) adds an Ed25519 signature from your signet, so readers who have your S2+PK announcement can check it was you. It costs 72 bytes per message, often one extra line.

A circle is a named shared secret. Announce the name in public chat if you want; the passphrase never goes in chat. Same name + passphrase on two devices produces the same key.

SIGIL is a public algorithm. Security lives in the keys, not in hiding how it works.

S2C.slug.blob — AES-256-GCM under a PBKDF2-SHA256 circle key (210000 iterations).
S2K.to.from.blob — P-256 ECDH + HKDF-SHA256 + AES-256-GCM.
S2E.to.blob — ephemeral P-256 sender key, then the same seal.
S2S.slug.blob — S2C seal whose last part ends with an 8-byte key id and an Ed25519 signature over every part, the message id and the circle.
Blob is header || [eph key] || nonce || ciphertext || tag in unpadded URL-safe base64. The header (flags, part i/n, 48-bit message id) is authenticated, so parts cannot be relabelled or spliced across messages, and fragments rejoin exactly. S1 tokens still open; pick S1 above for old peers.

AAD binds the circle or the direction so a valid token cannot be silently retargeted. Observers learn that a sealed message exists and which slug or short-id it is for. They do not learn the plaintext and cannot forge a token without the key.

Not a Minecraft mod. Not anonymous. Not post-quantum. Meant for channels you do not control.

Protocol S2 (opens S1) · keys live in this browser's localStorage · no network requests after the page loads.
